# Narwhal — 深潜，立起你的专家身份

> Narwhal · Dive deep. Stand out.（独角鲸：深潜，成家。）
> 把散落的个人经验"深潜"成结构化知识，用知识地图与领域技能立起专家身份。这不是建百科——是把你验证过的经验编译成可复用的专家资产。

## 核心理念

1. **经验 > 信息**：只沉淀"我经历过、验证过、有独家判断"的内容，不搬运通用知识。
2. **条目原子化**：一个条目讲透一个知识点/方法/教训，500~1500 字。
3. **互联成网**：条目之间必须双向链接，孤岛条目是失败的知识库。
4. **地图优先**：先建 MOC（Map of Content），再填条目；没有地图的知识库会失序。
5. **编译而非检索**（Karpathy llm-wiki 模式）：知识编译一次、持续维护，而非每次查询临时检索；源材料不可变，条目由 agent 拥有并维护。
6. **分工**：人负责策展源材料、指方向、确认经验；agent 负责摘要、交叉引用、归档、一致性维护。

## 领域知识库与技能输出

### 按领域组织

一个 wiki 可以包含多个**领域**（domain），每个领域是独立的子知识库：

```
wiki/entries/<领域>/   wiki/cases/<领域>/   wiki/moc/<领域>.md
```

领域由发现阶段自动聚类提出（见模式 E），最终由用户确认。领域数量控制在 3~7 个：太少说明聚类粒度过粗，太多说明需要合并。

### 领域工作技能输出（skill-forge）

领域知识库积累到一定程度（该领域 ≥5 条目 + ≥2 案例）后，可按用户指令把该领域"编译"为一个**可交付的工作技能**，产出物（默认写到 `wiki/exports/<领域>/`）：

1. **`SOP.md`** — 该领域标准作业流程：从 methods/ 和高 confidence 条目提炼，步骤化、可执行。
2. **`CHECKLIST.md`** — 该领域开工前检查清单：从 pitfall 条目反向推导（每个踩坑 → 一条检查项）。
3. **`PLAYBOOK.md`** — 实战手册：精选 cases/ 复盘（背景-做法-结果-教训），按场景索引。
4. **`BRIEF.md`** — 领域简报：我的专家主张、能力边界、可承接的任务类型（对外展示用）。
5. **`skill.md`**（可选）— 打包为 Agent Skill 格式：把 SOP+CHECKLIST+条目精华压缩成一份 SKILL.md，安装后即可在该领域工作中自动生效。

输出原则：只引用 wiki 内已验证内容，confidence 低的条目不进入 SOP/CHECKLIST；每份输出注明引用的来源条目。

## 知识库目录结构（三层架构）

知识库根目录默认为 `<工作区>/wiki/`（用户指定则从其指定）：

```
wiki/
├── SCHEMA.md                  # 第3层：约定——目录规则、条目模板引用、标签体系、领域配置
├── HOME.md                    # index：内容目录 + 每条一句话摘要 + 最近更新
├── log.md                     # 追加式动作日志（YYYY-MM-DD + 做了什么），只增不删
├── raw/                       # 第1层：不可变源材料——原文、对话记录、文档、笔记导入
│   └── <YYYY-MM-DD>-<来源名>.md
├── moc/                       # 第2层：知识地图（Map of Content），按领域一图一文件
│   └── <领域名>.md
├── entries/                   # 第2层：原子知识条目（agent 拥有，可增改）
│   └── <领域>/<条目名>.md
├── cases/                     # 第2层：经验案例：真实事情经过 + 复盘
│   └── <领域>/<案例名>.md
├── methods/                   # 第2层：个人方法论/SOP/检查清单
│   └── <方法名>.md
└── profile/
    ├── EXPERT-PROFILE.md      # 专家画像：身份定位、能力矩阵、代表作
    └── OPEN-QUESTIONS.md      # 待深潜问题清单（驱动下一轮输入）
└── exports/                   # 领域技能输出物（SOP/CHECKLIST/PLAYBOOK/BRIEF/skill.md）
    └── <领域>/
```

规则：
- `raw/` 一经写入**永不修改**；agent 只读取，任何提炼都落到 entries/cases。
- 条目中引用源材料时，用相对链接指向 `raw/` 对应文件。
- 每次任何写操作（新建/更新/体检）结束后，**必须在 log.md 末尾追加一行**：`- YYYY-MM-DD | 模式X | 动作摘要`。

## 会话恢复仪式（orientation，每次必须先做）

面对已有 wiki，做任何 ingest/query/lint 之前，必须依次：

1. 读 `SCHEMA.md` —— 了解领域配置与约定。
2. 读 `HOME.md` —— 了解已有哪些条目及摘要，避免重复建页、漏交叉引用。
3. 读 `log.md` 最后 20~30 行 —— 了解最近做过什么。
4. 条目超过 100 篇时，先用 Grep 按关键词搜一遍，再决定新建还是更新。

## 条目模板（assets/templates/entry.md）

必填字段（YAML frontmatter）：

```yaml
---
title: 条目标题
domain: 所属领域
type: concept | method | pitfall | insight | resource   # 概念/方法/踩坑/洞察/资源
confidence: 高 | 中 | 低          # 我对这条经验的确信度
source: 经验来源（项目/事件/阅读）
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: []
links: ["[[相关条目]]"]           # 双向链接，[[ ]] 语法
---
```

正文固定三段：**一句话结论 → 展开与个人判断 → 适用边界/反例**。

## 案例模板（assets/templates/case.md）

**背景 → 我做了什么 → 结果 → 复盘（学到什么/下次怎么做）→ 关联条目**。

## 工作流

### 模式 A：初始化（cold start）

用户第一次建库，或想从零规划时：

1. 与用户对齐：专家身份定位（"你想成为什么领域的专家"）、已有素材（文档/笔记/对话记录/网盘文件）。
2. 用素材（若无素材则用访谈提问）提炼 3~5 个**领域**，每个领域列 5~10 个候选条目与案例。
3. 创建完整目录结构（含 SCHEMA.md、log.md、raw/），并把提炼出的领域配置写进 SCHEMA.md。
4. 已有素材原样归档进 `raw/`，再从 raw 提炼第一批条目（每领域至少 1 条，宁缺毋滥，没有真实经验的领域标记为"待验证"）。
5. 在 log.md 记录初始化动作。

### 模式 B：深潜（ingest）

用户丢来一段经历/对话/文档，或说"帮我把这个沉淀下来"：

0. 先执行会话恢复仪式（orientation）。
1. **归档源材料**：原文原样存入 `raw/<YYYY-MM-DD>-<来源名>.md`，永不修改。
2. **提炼**：从 raw 中识别知识点、方法、踩坑、结论。逐条向用户确认哪些值得入库（避免噪音）。
3. **入库**：按模板写成条目/案例，并回链 raw 源文件；与现有条目交叉比对——已有则更新（增补判断、修改 confidence、标记矛盾），没有则新建并链接相邻条目。
4. **更新地图**：把新条目挂进对应 MOC；若出现新领域则新建 MOC 并更新 HOME.md。
5. **更新画像**：若本次经验提升了某项能力或新增代表作，更新 EXPERT-PROFILE.md。
6. **反哺问题**：沉淀过程中发现的空白与疑问写入 OPEN-QUESTIONS.md，向用户抛出 1~2 个值得深潜的问题。
7. **记日志**：log.md 追加一行本次动作。

### 模式 C：导航（query）

用户问"我关于 X 积累了什么"：

0. 先执行会话恢复仪式（orientation）。
1. 从 HOME.md 或 moc/ 找到相关地图 → 顺链接读条目 → 以"条目引用 + 个人判断原文"方式回答。
2. 若库中无相关内容，如实回答并建议是否把这段对话沉淀入库。

### 模式 D：体检（lint）

用户说"体检/检查知识库/lint"，或每次大额入库后主动建议：

1. 运行 `scripts/wiki_tool.py doctor <wiki根目录>`：断链、孤儿条目、缺失元数据。
2. **矛盾检测**（脚本之外，agent 判断）：扫描同领域条目，若两条结论互相冲突，在两条条目中互相标注 `> ⚠️ 与 [[对方条目]] 存在矛盾：……` 并提交用户裁决。
3. **覆盖缺口**：对照 OPEN-QUESTIONS.md 与 MOC 中的"待深潜"，向用户报告哪些领域长期没有新条目。
4. 体检结果与修复动作记入 log.md。

### 模式 E：全域扫描（discover）

用户说"扫描我的资料/自动发现/帮我建领域库"时，从散落文档自动建领域知识库：

**1. 采集**（按顺序扫描，找到什么读什么）：
- 本地：用户指定目录、`/root/uploads/`（用户上传）、`/workspace/`（工作区文档）。
- 云端：项目网盘/云文档（如 tdrive），**只读不写**——云端文件绝不修改，需要沉淀的内容拷贝进 `raw/`。
- 支持 md/txt/docx/pdf/xlsx/pptx/csv 等常见格式；二进制文档用对应工具解析为文本。

**2. 分诊**（每份文件快速打标，不精读）：
- `经验` — 我做过的事的记录（复盘、总结、周报、方案、会议纪要）→ 优先入库
- `参考` — 别人的知识/行业资料 → 只挑与用户领域相关的少数条目，标 `confidence: 低·外部参考`
- `噪音` — 无关文件 → 跳过并告知用户扫描统计（读了 N 份、经验 X、参考 Y、跳过 Z）

**3. 聚类分域**：对经验类文档按主题聚类（依据：文件名、关键词、业务对象、反复出现的场景），提出 3~7 个候选领域，**连同每域的代表文件清单提交用户确认/改名/合并**。

**4. 批量入库**：确认后走模式 B 流程逐文件深潜（每域先出 MOC 和高价值条目，长尾文件按批次继续，每批向用户汇报进度）。

**5. 更新 SCHEMA.md 领域配置表与 log.md。**

纪律：
- 单次扫描最多精读 20 份文件，超出的先列清单让用户排优先级，防止上下文爆炸。
- 扫描结束必须给统计报告：文件来源分布、领域聚类结果、入库数量、建议的下一个深潜主题。

## 质量红线

- 未经用户确认的经验，标 `confidence: 低` 并注明"待验证"。
- `raw/` 不可变；log.md 只追加；SCHEMA.md 是唯一结构权威。
- 不搬运网上随处可见的通用知识；通用背景最多一句话带过并给链接。
- 每次入库后必须检查：新条目是否至少链接了 1 个已有条目？没有则主动找用户确认关联。
- 每次更新 HOME.md 的"最近更新"区块。

## 写作风格

第一人称专家视角，直接、有立场（"我后来改成 X，因为 Y"），拒绝百科腔。条目结尾用一行"⭐ 一句话给三年后的自己"。
